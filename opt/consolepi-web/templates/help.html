Připojení ke konzolovému kabelu ze SecureCRT

Každý USB kabel má vlastní SSH port. SecureCRT se připojuje technickým účtem console a ConsolePi automaticky otevře správnou sériovou konzoli. 1

Vytvořte novou relaci

V SecureCRT zvolte File → Quick Connect nebo New Session a jako protokol vyberte SSH2.

2

Zadejte IP adresu a port

3

Nastavte uživatele

Do pole Username napište přesně console. Nepoužívejte administrační účet consolepi.

4

Vyberte správnou metodu autentizace

Režim se nastavuje v ConsolePi → Autentizace a platí pro všechny konzolové SSH porty. V SecureCRT vždy zůstává SSH username console; liší se pouze níže vybraná metoda.

Lokální heslo pro účet console
V Session Options → SSH2 → Authentication povolte pouze Password. Při spojení zadejte heslo účtu console, které nastavil správce ConsolePi. Nepovolujte PublicKey ani Keyboard Interactive.
Ukázka nastavení Password · otevřít v plné velikosti
SSH klíč pro účet console
Povolte pouze PublicKey a v jeho Properties vyberte privátní soubor vytvořený v ConsolePi. Do pole Username patří stále console; soubor s příponou .pub se nepoužívá.
Ukázka nastavení PublicKey · otevřít v plné velikosti
Vytvoření osobního klíče:
  1. V ConsolePi otevřete Přístupové klíče a zvolte vytvoření klíče.
  2. Zadejte popisné jméno osoby nebo počítače; ochranná fráze je doporučená.
  3. ConsolePi uloží pouze veřejný klíč, který dovolí přístup účtu console.
  4. Privátní klíč se nabídne k jednorázovému stažení do počítače. Uložte jej do chráněné složky; ConsolePi jej později neumí znovu zobrazit ani stáhnout.
  5. V SecureCRT otevřete Session Options → SSH2 → Authentication → PublicKey → Properties, zvolte Use session public key setting a Use identity or certificate file. Potom vyberte stažený privátní soubor.
Výběr souboru privátního klíče v SecureCRT · otevřít v plné velikosti
RADIUS – osobní uživatel a heslo
Povolte pouze Keyboard Interactive. SecureCRT nejprve otevře SSH jako console, pak se zeptá na RADIUS uživatel a jeho heslo. Tyto osobní údaje se na ConsolePi neukládají.
Ukázka nastavení Keyboard Interactive · otevřít v plné velikosti

Vždy zvolte pouze jednu metodu. Kombinace PublicKey + Password nebo PublicKey + Keyboard Interactive pro konzolové porty nefunguje a není vyžadována. Port 22 pro správu Raspberry Pi je samostatný a jeho pravidla se tím nemění.

5
{% if auth.mode == "radius" %}

Nastavte RADIUS přihlášení

  1. Otevřete Session Options → SSH2 → Authentication.
  2. Povolte metodu Keyboard Interactive. PublicKey není v RADIUS režimu potřeba.
  3. Po připojení zadejte do výzvy RADIUS uživatel své osobní jméno.
  4. Do výzvy Password zadejte své RADIUS heslo.

RADIUS jméno ani heslo se na ConsolePi neukládá. Při nedostupnosti obou serverů se konzole neotevře.

{% elif auth.mode == "local_password" %}

Nastavte přihlášení heslem

  1. Otevřete Session Options → SSH2 → Authentication.
  2. Povolte metodu Password. PublicKey ani Keyboard Interactive nejsou potřeba.
  3. Připojte se uživatelem console a zadejte lokální heslo nastavené správcem.

Lokální heslo je společné pro přístup ke všem konzolovým portům. Na zařízení je uložen pouze jeho systémový hash.

{% else %}

Vytvořte nebo vyberte privátní klíč

Nemáte-li ještě klíč, otevřete stránku Přístupové klíče, vytvořte jej a stažený soubor bezpečně uložte.

  1. Otevřete Session Options → SSH2 → Authentication.
  2. Povolte metodu PublicKey a otevřete její Properties.
  3. Zvolte Use session public key setting.
  4. Vyberte Use identity or certificate file.
  5. Tlačítkem … vyberte soubor consolepi-admin. Nevybírejte consolepi-admin.pub.

Privátní klíč je tajný. ConsolePi jej po stažení neuchovává. Neposílejte jej e-mailem a neukládejte jej na veřejné úložiště. Při ztrátě vytvořte na stránce Přístupové klíče nový a starý odeberte.

Zapomenuté heslo webu

Přihlaste se administrativním SSH jako consolepi na port 22 a v terminálovém menu zvolte Obnovit heslo webové administrace. Ze shellu lze stejnou bezpečnou obnovu spustit příkazem sudo consolepi-reset-web-password. Staré webové heslo není potřeba; oprávnění je ověřeno administrativním SSH účtem a pomocí sudo.

{% endif %}

V Session Options → Terminal → Emulation zvolte Xterm nebo VT100. SecureCRT musí požádat o interaktivní terminál.

C

Logování relace v SecureCRT

Log SecureCRT se ukládá na váš počítač, tedy nezávisle na logování ConsolePi. Je vhodný pro osobní pracovní záznam konkrétní relace.

  1. Uložte relaci SecureCRT a otevřete Session Options → Terminal → Log File.
  2. Do Log file name zadejte cestu v existující složce. Na macOS například: /Users/<uživatel>/Documents/ConsolePi-logs/%S-%H-%P-%Y%M%D-%h%m%s.txt.
  3. Zaškrtněte Start log upon connect, aby pro každé spojení vznikl samostatný soubor.
  4. Volitelně zaškrtněte Timestamp each line, pokud chcete čas u každého zaznamenaného řádku.
  5. V Session Options → Connection → Logon Actions nechte vypnuté Display logon prompts in terminal window. U SSH tak SecureCRT začne zapisovat až po úspěšném přihlášení, nikoli během zadávání RADIUS hesla.

Pro jednorázové ruční spuštění nebo ukončení záznamu použijte v hlavním menu SecureCRT položku File → Log Session.

Chraňte klientské logy. Cisco zařízení může zpětně vypsat konfiguraci, tajné údaje nebo zadané příkazy. Ukládejte záznamy do chráněné složky, nesdílejte je e-mailem a po vyřešení práce je smažte. Pro běžný provoz je bezpečnější logování pouze událostí na ConsolePi.

L

Logování na ConsolePi a ochrana citlivých údajů

V nabídce Systém → Logování konzolových portů lze vybrat jednu ze tří úrovní:

Pouze události
Ukládá jen připojení a odpojení USB kabelů. Nezaznamenává žádný obsah terminálu a představuje nejbezpečnější výchozí volbu.
Pouze výstup zařízení
Neukládá samostatný vstup uživatele. Řádky obsahující výrazy jako password, secret, community string, token nebo privátní klíč nahrazuje značkou [CITLIVY OBSAH ODSTRANEN].
Úplný obousměrný přepis
Ukládá vstup i výstup bez obsahové redakce. Používejte pouze při vědomém řešení incidentu a log po skončení odstraňte.

Redakce není absolutní záruka. Síťové zařízení může heslo, klíč nebo konfiguraci vypsat v neočekávaném formátu. Pokud nesmí být zaznamenán žádný tajný údaj, použijte režim Pouze události.

Přepisy jsou rozdělené podle portů 2201–2204. Starší soubory se komprimují a limity celkové velikosti, jedné relace, doby uchování a volného místa chrání SD kartu před zaplněním. Tlačítko Prohlížet logy zpřístupní bezpečný náhled a Vymazat logy odstraní dokončené záznamy.

P

Přístup k aktualizacím přes proxy

Pokud management síť nepovoluje přímý přístup do internetu, otevřete Síť → HTTP/HTTPS proxy, zapněte proxy a zadejte její adresu a port. Uživatelské jméno a heslo vyplňte pouze tehdy, pokud je proxy vyžaduje.

Položka Nepoužívat proxy pro obsahuje lokální adresy a domény, které mají být dostupné přímo. Hodnoty oddělujte čárkou.

Uložené heslo smí číst pouze uživatel root. Web zobrazuje jen informaci, že heslo existuje, nikdy jeho obsah.

R

APT repozitáře a lokální mirror

V Síť → APT repozitáře ponechte Oficiální Debian a Raspberry Pi repozitáře, pokud zařízení může aktualizace stahovat přímo nebo přes proxy.

Pro síť bez internetu zvolte Vlastní lokální mirror a zadejte tři HTTP/HTTPS adresy: Debian, Debian Security a Raspberry Pi. ConsolePi nejprve ověří všechny zdroje odděleným stažením indexů; při selhání původní konfiguraci nezmění.

Stejná volba je dostupná i v terminálovém administračním menu jako APT repozitáře (oficiální / lokální mirror). Proxy a mirror jsou nezávislé volby. Proxy případně nastavte samostatně v předchozí části. Při přípravě generic image se vždy obnoví oficiální zdroje a odstraní se proxy i další lokální APT zdroje.

F

Povolené zdroje přístupu

V nabídce Síť → Povolené zdroje přístupu se spravuje firewall ConsolePi. Stejný seznam lze přidávat a odebírat také z terminálového administračního menu volbou Povolené management sítě (firewall), například ještě před změnou IP adresy do jiné sítě. Pravidla platí současně pro webovou administraci HTTPS, administrativní SSH na portu 22 i konzolové SSH porty 2201–2204.

Řádek Lokální Ethernet je automatický a nelze jej upravit ani odstranit. Po změně IPv4 nastavení se sám přepíše na aktuální přímo připojenou síť, například 10.176.122.0/24.

  1. Zadejte vlastní popis, například Správní VPN nebo NOC.
  2. Zadejte jednu IPv4 adresu, například 10.247.227.8, nebo celou síť v CIDR zápisu, například 10.247.0.0/16.
  3. Potvrďte tlačítkem Povolit zdroj. Všechny zdroje, které nejsou v tabulce, firewall odmítne.

Hodnota 0.0.0.0/0 je podporovaná, ale otevře ConsolePi pro celý IPv4 internet. Proto je nutné navíc do potvrzovacího pole napsat přesně POVOLIT VŠEM. Používejte ji jen ve výjimečném, vědomě zabezpečeném nasazení.

Před odstraněním vlastního zdroje ověřte, že stále zůstáváte v automatické lokální síti nebo máte jinou povolenou cestu. Jinak se k zařízení vzdáleně nepřipojíte.

N

Bezpečná změna síťové konfigurace

V nabídce Síť → Ethernetové připojení lze přepnout mezi DHCP a statickou IPv4 adresou. Po kontrole a odeslání se změna provede po krátké prodlevě, aby se dokončila odpověď prohlížeči.

  1. Pokud nová adresa patří do jiné sítě, přesuňte do ní také administrátorský počítač nebo upravte jeho síťové připojení.
  2. V prohlížeči otevřete https://NOVÁ-IP/admin?tab=network a znovu se přihlaste.
  3. Po skutečném připojení rozhraní se zobrazí blok Nepotvrzená změna s odpočtem a tlačítkem Potvrdit nové síťové nastavení.
  4. Potvrďte ji do 180 sekund. Pokud čas vyprší, ConsolePi automaticky vrátí původní síťový profil i firewall; prohlížeč se poté pokusí otevřít původní adresu.

Potvrzení v terminálovém administračním menu je záložní možnost. Výzva se ukazuje pouze po aktivaci nové konfigurace, ne během její přípravy.

Před změnou do jiné sítě ji podle potřeby přidejte do seznamu povolených zdrojů přístupu. Jinak vás firewall může po úspěšné změně adresy správně odmítnout.

G

Generic image a první spuštění

Generic image vybírejte v Raspberry Pi Imageru z repozitáře ConsolePi. V OS Customisation ponechte účet consolepi, nastavte pouze jeden veřejný klíč typu ssh-ed25519 a nenastavujte heslo ani jiné změny uživatele, hostname nebo Wi-Fi.

Při prvním spuštění je do dokončení webového průvodce dočasně povolen přístup na porty SSH 22 a HTTP/HTTPS 80/443 z IPv4 adres. Je to pouze instalační režim; po dokončení průvodce se veřejný přístup uzavře.

  1. Otevřete web ConsolePi na adrese získané z DHCP nebo nastavené v síti.
  2. V průvodci vyplňte identitu zařízení, heslo webové administrace a jednu nebo více management IPv4 sítí. Sítě lze oddělit čárkou nebo mezerou; alespoň jedna musí obsahovat adresu použitého prohlížeče.
  3. Po dokončení jsou SSH, web a konzolové porty omezeny na uložené management sítě. Uchovejte si použitý administrativní privátní SSH klíč mimo ConsolePi.

Generic image neobsahuje privátní administrativní klíč, sdílené heslo ani identitu původního zařízení. Pokud Imager předá chybějící nebo neplatný klíč či jinou nepovolenou customizaci, provisioning skončí uzavřeně a vyžaduje lokální recovery postup.

A

Aktualizace systému

ConsolePi kontroluje dostupné balíčky automaticky jednou denně. Stav, poslední kontrola a seznam dostupných balíčků jsou v nabídce Systém → Zařízení.

Tlačítko Zkontrolovat nyní obnoví seznam balíčků na pozadí. Instalace se nikdy nespouští automaticky; musí ji potvrdit správce textem AKTUALIZOVAT.

Během instalace Raspberry Pi nevypínejte. ConsolePi používá bezpečnější apt upgrade, zachovává lokální konfigurační soubory a po dokončení oznámí, zda je nutný restart.

S

Údržba, zálohy a klonování

Bezpečnostní kontrola
V nabídce Systém upozorňuje na nesynchronizovaný čas, neaktivní firewall, docházející disk, certifikát a způsob autentizace.
Šifrovaná záloha
Soubor .cpbackup je chráněn heslem. Volba citlivých údajů navíc zahrne autentizační secrets, přístupové klíče a privátní TLS klíč.
Diagnostika
Balíček obsahuje stav systému a služeb. Hostname, IP a MAC adresy se anonymizují; hesla, privátní klíče a sériové přepisy se nepřidávají.
NTP
Pro správné logy a RADIUS udržujte stav Synchronizováno. Interní NTP servery zadávejte oddělené čárkou.
HTTPS certifikát
Lze stáhnout veřejnou část, nahrát certifikát firemní CA nebo vytvořit nový lokální certifikát.
Tovární reset
Vymaže provozní nastavení, mapu kabelů a logy, nastaví DHCP a zobrazí průvodce prvního spuštění. Nejde o zálohu ani o aktualizaci systému.
Klon SD karty
Na nové fyzické kartě se průvodce prvního spuštění spustí automaticky a vytvoří novou identitu, webové heslo, SSH hostitelské klíče a HTTPS certifikát. Ruční změna identity proto pro běžný klon není potřeba.
Regenerace SSH a HTTPS identity
V nabídce Systém → Údržba ji použijte pouze při bezpečnostním incidentu nebo pokud potřebujete vyměnit SSH hostitelské klíče a HTTPS certifikát bez továrního resetu. Uložení názvu zařízení a hostname tuto akci nespouští.

Heslo šifrované zálohy ConsolePi nikde neukládá. Při jeho ztrátě nelze zálohu obnovit.

!

Řešení problémů

Unable to authenticate
Ověřte username console a metodu odpovídající aktivnímu režimu: Password pro lokální heslo, PublicKey pro SSH klíč nebo Keyboard Interactive pro RADIUS. Nikdy nezapínejte několik metod najednou.
RADIUS se neověří
V ConsolePi otevřete Autentizace a znovu uložte konfiguraci. Při uložení se zobrazí úspěch, nebo konkrétní chyba spojení/secretu. Po změně NAS záznamu v daloRADIUS restartujte na RADIUS serveru službu freeradius, aby načetla nové nastavení klienta.
SecureCRT nevytváří log
Ověřte, že cesta v Terminal → Log File existuje a je zapisovatelná, a že je zapnutá volba Start log upon connect. Pro ruční ovládání použijte File → Log Session.
Je vyžadován terminál
Povolte v relaci SecureCRT požadavek na pseudo-terminal a použijte interaktivní SSH relaci.
Konzole je obsazena
Ke stejnému kabelu je již připojen jiný uživatel. Počkejte na ukončení jeho relace.
Offline
USB adaptér není připojen k Raspberry Pi nebo neodpovídá uloženému sériovému ID.
Terminál je prázdný
Zkontrolujte zapojení do console portu Cisco zařízení a několikrát stiskněte Enter.
