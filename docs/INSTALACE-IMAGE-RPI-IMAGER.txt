ConsolePi+ – instalace vlastní SD image pomocí Raspberry Pi Imageru
===================================================================

Tento postup je určen pro připravený soubor ConsolePi+ ve formátu .img.xz.
Soubor nerozbalujte. Raspberry Pi Imager jej umí zapsat přímo.

UPOZORNĚNÍ
---------
Zápis image kompletně smaže vybranou SD kartu. Před pokračováním ověřte,
že jste vybrali opravdu SD kartu pro ConsolePi+, nikoli interní disk počítače.

CO JE POTŘEBA
-------------
- Raspberry Pi 3 Model B nebo B+
- kvalitní microSD karta s kapacitou alespoň 8 GB
- napájení Raspberry Pi
- ethernetový kabel do sítě s DHCP (doporučeno pro první spuštění)
- počítač s Raspberry Pi Imagerem a SSH klientem
- soubor ConsolePi-...img.xz
- vlastní Ed25519 veřejný SSH klíč správce (soubor s příponou .pub)

KROK 1 – ZÁPIS IMAGE
---------------------
1. Vložte SD kartu do počítače.
2. Otevřete Raspberry Pi Imager.
3. Klikněte na „Choose Device“ a vyberte Raspberry Pi 3.
4. Klikněte na „Choose OS“ a vyberte **ConsolePi Plus Generic Image** z
   ConsolePi Plus custom repository. Přímé „Use custom“ v Imageru 2.0.x
   OS Customisation pro vlastní image nezpřístupní, proto není podporované.
5. Použitá položka repository musí deklarovat `init_format: systemd`.
6. Klikněte na „Choose Storage“ a vyberte správnou SD kartu.
7. Otevřete nastavení OS customizace:
   - v části General NEZAPÍNEJTE „Set username and password“; účet consolepi
     je už v image a jeho systémové heslo je uzamčené,
   - v Services zapněte SSH, vyberte výhradně „Allow public-key
     authentication only“ a vložte jeden vlastní veřejný klíč Ed25519,
   - nikdy nevkládejte soukromý klíč (soubor bez přípony .pub),
   - hostname, Wi-Fi a ostatní volby ponechte beze změny; první připojení
     generic image je určené pro ethernet s DHCP.
   V celé OS Customisation nesmí být aktivní žádná jiná změna než SSH
   public-key authentication. I automaticky předvyplněné volby hostname,
   locale, timezone nebo Wi-Fi výslovně vypněte.
8. Klikněte na „Write“ a potvrďte smazání SD karty.
9. Vyčkejte na dokončení zápisu i ověření („Verification successful“).
10. SD kartu bezpečně vysuňte.

KROK 2 – PRVNÍ START
--------------------
1. Vložte SD kartu do Raspberry Pi.
2. Připojte ethernet a napájení.
3. Vyčkejte přibližně dvě až tři minuty na první start.
4. Z DHCP serveru, routeru nebo síťového skeneru zjistěte IPv4 adresu RPi.

KROK 3 – DOKONČENÍ VE WEBU

Po dobu nedokončeného generic first bootu jsou z IPv4 sítí dočasně
dostupné pouze porty SSH 22 a web 80/443. Port 80 pouze přesměrovává na
HTTPS. Sériové SSH porty 2201–2204, SNMP a ostatní služby zůstávají
chráněné management allowlistem.

1. V prohlížeči otevřete:

   https://IP_ADRESA_RPI/

2. Prohlížeč upozorní na vlastní HTTPS certifikát. To je při prvním spuštění
   očekávané; pokračujte na stránku zařízení.

3. Nastavte heslo webové administrace, identitu zařízení a jednu nebo více
   povinných IPv4 management sítí v CIDR tvaru (např. `192.168.1.0/24,
   10.20.0.0/16`). Sítě oddělte čárkou nebo mezerou. Alespoň jedna musí
   obsahovat adresu počítače, ze kterého průvodce dokončujete; hodnota
   `0.0.0.0/0` není povolena.

4. U generic image se při prvním spuštění zachovává SSH veřejný klíč vložený
   Raspberry Pi Imagerem. Tento klíč je považován za ověřený už při bezpečném
   importu z Raspberry Pi Imageru.

5. Dokončete průvodce. Nejdříve se aktivuje zadaný management allowlist
   a odstraní dočasný globální přístup; teprve potom se generic-image stav
   změní na `complete`.

KROK 4 – SSH PO PRVNÍM SPUŠTĚNÍ
-------------------------------
Průvodce vytvoří nové SSH hostitelské klíče. Pokud byla tato IP adresa dříve
použita jiným Raspberry Pi nebo starší instalací, odstraňte na svém počítači
starý fingerprint:

macOS / Linux:
    ssh-keygen -R IP_ADRESA_RPI

Windows PowerShell:
    ssh-keygen -R IP_ADRESA_RPI

Pak se připojte znovu. Při použití vlastního privátního klíče například:

macOS / Linux:
    ssh -i "$HOME/.ssh/consolepi-admin" consolepi@IP_ADRESA_RPI

Windows PowerShell:
    ssh -i "$env:USERPROFILE\.ssh\consolepi-admin" consolepi@IP_ADRESA_RPI

KROK 5 – USB KONZOLE
--------------------
1. Připojte USB–RS232 konzolové kabely.
2. Otevřete web ConsolePi+ a přihlaste se jako administrátor.
3. V přehledu přiřaďte nově nalezenému kabelu port 2201 až 2204.
4. Nastavte popis cílového zařízení a podle potřeby sériové parametry.
5. Připojení na první konzoli například:

    ssh -tt -p 2201 console@IP_ADRESA_RPI

V SecureCRT nastavte host IP_ADRESA_RPI, port 2201 až 2204, uživatele console
a způsob ověření zvolený v ConsolePi+ (heslo, PublicKey nebo Keyboard Interactive
pro RADIUS).

POZNÁMKA K VELIKOSTI SD KARTY
-----------------------------
Image je zmenšený pro snadné šíření. Po zápisu na větší SD kartu není zbývající
kapacita využita automaticky, dokud ji nepotvrdíte v průvodci prvního spuštění
nebo později v administraci ConsolePi+ v části Systém.

RYCHLÁ DIAGNOSTIKA
------------------
Administrativní SSH:
    ssh -i CESTA_K_PRIVATNIMU_KLICI consolepi@IP_ADRESA_RPI

Verze ConsolePi+:
    cat /usr/share/consolepi/VERSION

Stav služeb:
    systemctl status consolepi-web nginx ssh nftables --no-pager

Diagnostika ConsolePi+:
    sudo consolepi-diagnose

PŘÍPRAVA GENERIC IMAGE (PRO SPRÁVCE VYDÁNÍ)
-------------------------------------------
Tento oddíl je pouze pro vytvoření distribuovatelného masteru. Na běžně
provozovaném ConsolePi+ jej nespouštějte.

1. Na referenčním zařízení s aktuální instalací ověřte, že účet consolepi má
   UID 1000 a že jsou nainstalované soubory generic-image režimu.
2. Z lokální konzole nebo přes SSH spusťte:

       sudo consolepi-prepare-generic-image --poweroff

   a potvrďte textem GENERIC. Program nejprve provede preflight a připraví
   náhradní konfigurace. Destruktivní část potom pokračuje v samostatné
   systemd úloze nezávislé na SSH relaci. Odpojení SSH je očekávané. Program
   odstraní hashe a uzamkne systémová hesla,
   odstraní všechny uživatelské SSH klíče, hostitelské SSH a TLS klíče,
   webová, RADIUS, SNMPv3, proxy a síťová tajemství, zálohy, historie, logy,
   machine-id, DHCP lease, cloud-init runtime stav a všechny NoCloud seedy
   z firmware partition. Integrace, identita, firewall allowlist a ethernet
   se resetují do neaktivního generického stavu s DHCP. Generic-only guardy
   chrání skutečné vendor entrypointy, které volá FAT payload Imageru. Povolí
   pouze `enable_ssh -k` s jediným Ed25519 veřejným klíčem a beze změny jej
   uloží účtu `consolepi`; userconf přijme jen účet `consolepi` s prázdným
   password argumentem. Imager nemusí při čistém key-only workflow userconf
   volat. Ostatní operace vytvoří write-once persistentní failure marker;
   první důvod se dalšími pokusy nepřepisuje. Metadata volání guardů se bez
   argumentů a tajemství ukládají do root-only `generic-imager-audit.jsonl`.
3. Po sanitizaci proběhne nezávislá kontrola masteru. Výsledek se atomicky
   uloží jako root-only report `/etc/consolepi/generic-image-validation.json`.
   Zařízení se automaticky vypne pouze při výsledku PASS. Při selhání zůstane
   zapnuté a fail-closed pro diagnostiku z lokální konzole; podrobnosti jsou v
   `journalctl -u consolepi-generic-image-preparation.service`. Sanitizovaný
   master už znovu nespouštějte před pořízením image vypnuté karty.
4. Image před zveřejněním připojte jen pro čtení a ověřte, že neobsahuje
   žádný authorized_keys, ssh_host_* ani consolepi.key a že /etc/machine-id
   má přesně first-boot hodnotu `uninitialized`.

Při prvním startu nejprve doběhne customizace Raspberry Pi Imageru. Služba
ConsolePi+ potom přijme právě jeden validní veřejný klíč ssh-ed25519 z účtu
consolepi, zkopíruje jej technickému účtu console a vytvoří nové hostitelské
SSH klíče, TLS klíč a webové tajemství. Pokud klíč chybí, je neplatný nebo má
nebezpečná oprávnění, SSH i web zůstanou zastavené. Po úspěchu vznikne
SSH veřejný klíč vložený Raspberry Pi Imagerem je použit jako počáteční administrativní přístup.
V OS Customisation smí být zapnuto pouze SSH s public-key authentication a
právě jedním Ed25519 klíčem. Username/password, hostname, Wi-Fi, locale,
timezone, keyboard, Raspberry Pi Connect a všechny další volby jsou
nepodporované. Po dokončení payloadu ConsolePi+ samostatně ověří účet, locked
password, klíč, login-capable účty, hostname, síťový profil, machine-id,
odstranění FAT payloadu a `systemd.run`. Teprve potom atomicky vytvoří success
marker; jakoukoli odchylku persistentně označí jako selhání a SSH ani web
neuvolní.
Stav `generic-imager-customization-failed` se restartem nemaže. Takovou kartu
nepřipojujte do sítě; z lokální konzole ověřte příčinu a připravte ji znovu
od čistého, úspěšně sanitizovaného masteru se správnou key-only customizací.

Pro vývojovou diagnostiku bez sítě lze na vypnuté kartě vytvořit prázdný soubor
`consolepi-recovery-enable` v kořeni firmware FAT partition. Při pending nebo
failed generic stavu se marker při příštím bootu jednorázově spotřebuje a pouze
na fyzickém tty1 se otevře diagnostický root shell. Provisioning zůstává
fail-closed; po `exit` ani při dalším bootu bez nového markeru se shell neobnoví.

Pokud se first boot přeruší před dokončením webového průvodce, spusťte
zařízení znovu; služba bezpečně pokračuje podle uloženého stavu. Je-li
`generic-image.json` chybějící nebo poškozený, provisioning zůstane
fail-closed. Stav ověřte z fyzické lokální konzole a při poškozeném nebo
neúplném generic stavu připravte image znovu z čistého, úspěšně
sanitizovaného masteru.

Selže-li regenerace SSH nebo TLS identity, ponechte zařízení mimo síť, opravte
příčinu (typicky plný/read-only filesystem nebo chybnou konfiguraci) a spusťte
provisioning znovu z lokální konzole. Aktivní klíče se při neúspěšném
nahrazení obnoví z lokální zálohy.


OBNOVA PO SELHÁNÍ SANITIZACE
----------------------------
Sanitizace je záměrně fail-closed. Při chybě zařízení nepřipojujte do sítě a
pokračujte pouze z lokální konzole. Skript vypíše příčinu, zapíše FAIL report
do `/etc/consolepi/generic-image-validation.json` a uloží postup do
`/etc/consolepi/generic-image-recovery.txt`. Preferovaný postup je odstranit
příčinu (například nedostatek místa nebo chybnou systemd jednotku) a spustit
`sudo consolepi-prepare-generic-image` znovu. Sanitizovaný master nepoužívejte
v provozu a image z něj nevytvářejte, dokud skript neskončí úspěšně.
